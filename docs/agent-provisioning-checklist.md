# dx-sensor エージェント設置手順（テナント拠点ごと）

新しいテナント拠点にカメラ+Raspberry Piエージェントを設置する際の標準手順。
**採用方式: 「キット内蔵ルーター方式」**
カメラのWi-Fiペアリングという壊れやすい工程をHenryさんの手元に完全に封じ込め、
テナント側の作業は「LANケーブルを挿すだけ」の1アクションに限定する。

---

## 方式概要

```
[Henryさんの手元で、この3点セットを丸ごと事前構築・動作確認]

  ┌───────────────────────────────────────┐
  │  小型トラベルルーター（Henryさんが用意・設定）        │
  │    SSID/パスワードはHenryさんが自由に決める独自の値     │
  │    ↓Wi-Fi                        ↓Wi-Fi/LAN         │
  │  [カメラ]                      [Raspberry Pi]        │
  └───────────────────────────────────────┘
              │ ルーターのWANポート
              │ (LANケーブル1本)
              ▼
      テナントの既存ルーターの空きLANポートに接続
```

- カメラは常にHenryさんが用意したトラベルルーターの電波に接続する。テナントのWi-Fi環境には一切依存しない
- トラベルルーターの内部は独立した専用サブネット(例: `192.168.50.0/24`)として動作するため、テナント側のネットワーク構成に左右されない
- トラベルルーターのWANポートをテナントのルーターにLAN接続することで、二重NAT構成にはなるが、エージェントは外向き通信のみ(Push型)のため問題にならない

---

## A. 事前準備（Henryさんの手元・ネット環境で）

### A-1. トラベルルーターの初期設定
1. 小型Wi-Fiルーター(トラベルルーター/モバイルルーター)を用意
2. 管理画面から、このキット専用のSSID・パスワードを設定（テナントごとに使い回してよい、テナント環境とは無関係な値でよい）
3. ルーターの動作モードを「ルーターモード」に設定（トラベルルーターの多くはAPモード/ルーターモードを切替可能。ルーターモードならWANポート接続先のネットワーク構成に依存せず独立サブネットを維持できる）

### A-2. カメラの初期設定
1. カメラ（開発機はTapo C210、本番機はReolink RLC/E1系）を、A-1で設定したトラベルルーターのWi-Fiに接続してペアリング
   - この時点でHenryさんの手元にトラベルルーターがあるため、通常のペアリング手順で問題なく成功する
2. カメラ側でONVIFを有効化し、ONVIF専用のユーザー名・パスワードを発行
   - Tapo: 「詳細設定 > カメラアカウント」
   - Reolink: 管理画面 > Network > Advanced > ONVIF
3. カメラに、トラベルルーターのサブネット内で固定IPを設定（例: `192.168.50.200`）
4. 疎通確認: `ONVIF Device Manager`等のツールで`GetSnapshotUri`が正常に動くことを確認

### A-3. テナント情報のDB登録
Supabase Studioで以下を作成（またはHenryさん向け管理画面ができるまでは手動）:
- `tenants`テーブルにテナントのレコードを作成
- `cameras`テーブルにカメラのレコードを作成（`vendor`, `host`=A-2で設定した固定IP, `port`, `username`, `secret_ref`）
- `parking_lots`, `parking_spots`テーブルに監視対象の駐車枠を作成

### A-4. エージェント用APIキーの発行
```bash
npx tsx scripts/issue-agent-key.ts \
  --tenant <tenant_id> \
  --camera <camera_id> \
  --label "<テナント名> - Pi #1"
```
出力された`dxs_agent_...`のキーを控えておく（この場限りでしか表示されない）。

### A-5. balenaCloudでのデバイス登録
1. balenaCloudダッシュボードで、まだフリートがなければ作成（例: `dx-sensor-agents`、Raspberry Pi 4を選択）
2. フリート内に新規デバイスを追加し、OSイメージをダウンロード
   - Network設定: 「Wi-Fi + Ethernet」を選択し、**A-1で設定したトラベルルーターのSSID/パスワード**を入力（Raspberry Pi自体はトラベルルーターの電波、または有線LANのどちらでもよい。有線の方が確実なため以下は有線を前提とする）
3. ダウンロードしたイメージを`balenaEtcher`でmicroSDカードに書き込む
4. balenaCloudダッシュボードで、この特定デバイスの **Device variables** に以下を設定
   ```
   CAMERA_HOST=192.168.50.200       ← A-2で設定した固定IP
   CAMERA_PORT=2020
   CAMERA_USER=<ONVIF用ユーザー名>
   CAMERA_PASS=<ONVIF用パスワード>
   PARKING_SPOT_ID=<parking_spots.id>
   INGEST_URL=https://<dx-sensorのドメイン>/api/ingest/vehicle-event
   AGENT_API_KEY=<A-4で発行したキー>
   POLL_INTERVAL_MS=60000
   DIFF_THRESHOLD=0.03
   ```
5. `agent/`ディレクトリのコードをこのフリートにpush
   ```bash
   cd ai-projects/dx-sensor/agent
   balena push dx-sensor-agents
   ```

### A-6. キット全体の結合動作確認（発送前に必ず実施）
1. トラベルルーター・カメラ・Raspberry Piを全て接続し、トラベルルーターのWANポートをHenryさんの手元のインターネット回線（自宅ルーター等）につなぐ
2. balenaCloudダッシュボードでRaspberry Piデバイスがオンラインになることを確認
3. ログを確認し、`pushed frame`のログが出て、`vehicle_events`テーブルに実際にレコードが増えることを確認
4. 問題なければ電源を切り、発送準備へ（**トラベルルーターの設定・カメラのペアリング状態はそのまま維持される**）

## B. 物理キットの準備

同梱物リスト:
- [ ] トラベルルーター本体（A-1で設定済み）
- [ ] トラベルルーター用電源アダプタ
- [ ] カメラ本体（A-2で設定済み・固定IP設定済み・トラベルルーターとペアリング済み）
- [ ] カメラ用電源アダプタ
- [ ] Raspberry Pi本体（A-5で設定済みSDカード挿入済み）
- [ ] Raspberry Pi用電源アダプタ（USB Type-C）
- [ ] Raspberry Pi ⇔ トラベルルーター間のLANケーブル（短め、キット内配線用）
- [ ] トラベルルーター ⇔ テナントルーター間のLANケーブル（テナント側で使う、長め）
- [ ] （念のため）簡易スイッチングハブ：テナントのルーターに空きLANポートがない場合の予備
- [ ] 簡単な設置説明書（D章の内容を1枚にまとめたもの）

## C. 配送

宅配便でテナント拠点へ発送。設置作業自体はテナント側で行うため、Henryさんの現地訪問は不要（ただし初回テナントは信頼関係構築も兼ねて訪問してもよい）。

---

## D. テナント側での作業（最小限・非技術者向け）

同梱の説明書には、以下のステップのみを記載する。

1. **カメラを監視したい場所に設置し、電源を挿す**（駐車場が見える位置等）
2. **トラベルルーターとRaspberry Piをそれぞれ電源に挿す**
3. **同梱の長いLANケーブルで、トラベルルーターとお手元のインターネットルーターをつなぐ**（どちらのポートに挿しても構わない旨を明記）
4. 以上で完了。数分後にHenryさんの方で正常動作を確認する

**テナントはWi-Fi情報を一切入力する必要がなく、カメラのペアリング作業も発生しない。**

---

## 解決済みの旧課題（記録として残す）

以前の検討段階で挙げていた以下の課題は、この「キット内蔵ルーター方式」の採用によりいずれも解消された。

1. ~~カメラのWi-Fi設定問題~~ → カメラは常にHenryさん専用のトラベルルーターに接続するため、テナントのWi-Fi環境を一切必要としない
2. ~~カメラの固定IP問題~~ → トラベルルーターが独立サブネットを提供するため、テナント側のネットワーク構成（サブネット等）に左右されない

## 残る軽微なリスク（有線LAN由来、発生頻度は低い）

- テナントのルーターに空きLANポートがない → 同梱の簡易ハブで対応
- テナント側ルーターでDHCPが無効化されている等の特殊環境 → 極めて稀。発生時は個別に電話サポート
