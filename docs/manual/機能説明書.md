## 1. プロダクト概要

dx-sensor は、**定点観測した画像を時系列で比較し、変化を AI で解析する汎用プラットフォーム**です。

- 観測対象は用途ごとに設定できます（駐車場の空き、設備の稼働、陳列・在庫、工事進捗など）。
- 最初のユースケースの一つが「スマホ定点監視 × 変化検知 × AI要約」であり、特定業種に固定した製品ではありません。
- 既存の dx-toolbox とは別プロダクトです（認証・RLS の設計パターンのみ参照）。

---

## 2. システム構成（概要）

| 層 | 内容 |
|----|------|
| アプリ | Next.js（App Router） / TypeScript |
| データ基盤 | Supabase（Auth・DB・RLS・Storage） |
| ホスティング | Vercel（定期ジョブ含む） |
| 画像解析 | Gemini 等の Vision API、必要に応じて ANPR |
| センサー取得 | スマホカメラ（実装済み）／クラウドカメラ・現場エージェント（基盤あり、管理UIは一部準備中） |

処理の基本の流れは次のとおりです。

1. **画像取得**（スマホ自動撮影、手動撮影、外部センサーなど）
2. **Storage へ保存**
3. **変化検知・AI解析**（画素差分 → 必要時に Vision）
4. **構造化データとして記録・画面表示**

## 3. 利用者と権限

メンバーの権限は `tenant_members.role` で管理します（メールアドレスのハードコードはしません）。

| ロール | 説明 |
|--------|------|
| owner | テナント所有者。テナント内の広い管理権限（RLS上） |
| admin | テナント管理者 |
| viewer | 閲覧中心 |
| developer | 開発者。クロステナント閲覧と**管理画面**へのアクセスが可能 |

補足:

- テナント画面のメニューは、現状ロールによる表示分岐はありません（ログイン＋所属テナントがあれば利用）。
- 管理画面（`/admin` 配下および `/debug`）は **developer** のみ。
- アクティブテナントは「所属の先頭1件」前提です（テナント切替UIは未実装）。

## 5. テナント画面（利用者向け）

入口: ログイン後の TOP（`/`）

### 5.1 定点監視カメラ

#### （1）スマホのカメラで定点監視（固定撮影）

| 項目 | 内容 |
|------|------|
| ルート | `/capture_auto` |
| 画面タイトル | 固定撮影 |
| 目的 | スマホを固定し、一定間隔で写真を自動撮影・保存する |

主な機能:

- カメラ起動（背面カメラ優先）
- **自動撮影開始 / 停止**（稼働中は「撮影中」表示などの状態表示あり）
- 撮影間隔: 3 / 5 / 10 / 15 / 30 / 60 秒
- **設置向き**（保存時の回転に使用）
  - 横置き固定（左に傾けて設置が標準）
  - 縦置き固定
  - 向きが違う場合の「回転方向を反転」
- カメラ枠の表示サイズは常に縦長。設置向きは**保存画像の向き**に反映
- 保存先: Storage `auto-captures` / テーブル `auto_captures`
- **画面を開くと、自分の前回の定点監視画像は削除**される（ヒントに記載）

#### （2）監視分析を見る

| 項目 | 内容 |
|------|------|
| ルート | `/capture_auto_analyze` |
| 画面タイトル | 監視分析 |
| 目的 | 固定撮影で貯めた画像を比較し、変化の大きさと AI 要約を確認する |

画面は 4 つのタブで構成されます。

##### a. 監視条件の設定

- システムテンプレートから用途を選んで適用（メーター読取、稼働ランプ、欠品、駐車場空き、行列、工事進捗など多数）
- 白紙からの作成も可能
- 監視項目スロット（ラベル＋値、最大 10）
- 通知先メールの設定（※現状は実メール送信ではなく、通知キュー記録まで）
- 設定の保存

##### b. 監視状況

- **監視開始 / 停止**（画面を開いている間のみ、約 **5 秒**ごとに処理）
- 監視カウント、開始時刻、ステータス表示
- ランプ表示
  - **緑**: 変化なし（差分が小さい → AI解析スキップ）
  - **黄**: 軽微な変化（記録するが通知対象外）
  - **赤**: 通知対象（大きな変化）
- 今回画像 / 前回画像の表示
  - 縦長画像は 2 枚横並び
  - 横長画像は 2 段表示
- AI への命令プロンプトの確認

##### c. アクティブ履歴（イベント履歴）

- 「すべて」／「イベントのみ」の表示切替
- 差分スコア・severity・メッセージ
- 画像番号（`#前→#後`）と、比較画像モーダル

##### d. 画像表示

- 自動撮影画像の一覧（未処理／処理済フィルタ）
- サムネイルをクリックすると**拡大プレビューモーダル**

処理の概要:

1. 未処理の定点画像を取得  
2. 画素差分で変化量を算出  
3. 閾値により skip / minor / notify を判定  
4. minor / notify のとき、前後 2 枚を Vision（Gemini）で要約

### 5.2 写真レポート

#### （1）写真レポートの送信

| 項目 | 内容 |
|------|------|
| ルート | `/send_picture` |
| 画面タイトル | 画像送信 |
| 目的 | 件名・本文付きで写真を撮影し保存する |

主な機能:

- 件名の選択（マスタ登録／都度入力）

- 直近の送信一覧
- 保存はユーザー単位（Storage `picture-sends`）

#### （2）写真フォルダーを見る

| 画面タイトル | 写真フォルダー |
| 目的 | 送信済み写真の一覧・編集・削除 |

主な機能:

- グリッド表示
- 件名によるフィルタ
- 本文の編集・削除

### 5.3 文書ホルダー（名刺）

#### （1）名刺を撮る

| 項目 | 内容 |
|------|------|
| ルート | `/documents/new?type=business_card` |
| 画面タイトル | 名刺を撮る |
| 目的 | 名刺の表面・裏面を撮影し、AIで連絡先情報を読み取って保存する |

主な機能:

- 表面撮影（必須）／裏面撮影（任意）
- Gemini による OCR と、保存前の確認・手修正
- メモ、タグ、会った日、会社公開の設定
- 重複候補がある場合の既存データ更新または閲覧誘導

#### （2）文書ホルダーを見る

| 項目 | 内容 |
|------|------|
| ルート | `/documents?type=business_card` |
| 画面タイトル | 文書ホルダー |
| 目的 | 保存済み名刺の一覧・検索・編集・会社公開管理 |

主な機能:

- 自分／会社公開／全部の表示切替
- タグ、会った日期間、氏名・会社名・メールによる検索
- グリッド／リスト表示、サムネイル付きの詳細モーダル
- OCR項目、メモ、タグ、会った日、会社公開の編集
- 保存済み画像の再解析、削除
- URL の `open` query による詳細モーダルの直接表示

伝票・明細テーブル（`captured_document_line_items` など）は v1 対象外です。

## 7. カメラ・センサー連携（設計方針）

- ベンダー差はセンサー／Driver 層に閉じ込め、業務画面からベンダー固有 API を直接呼びません。
- 開発想定: Tapo 等（ONVIF）／本番想定: Reolink 等（ONVIF）。切り替えは設定（vendor）中心。
- クラウドカメラ（SoraCam）や現場エージェント（balenaCloud + ONVIF）向けの取得経路もコード上にあります。
- 利用者が日常的に使う実装済み経路は、現状 **スマホカメラによる定点監視・写真レポート** が中心です。

---

## 8. データとプライバシーに関する注意

- 画像や解析結果はテナント（またはユーザー）単位で隔離し、RLS で保護します。
- ナンバープレート等、個人情報に該当しうるデータを扱う場合は、利用目的・保存期間・アクセス制御に留意してください。
- 認証情報は DB に平文保存せず、参照（シークレット参照）で管理する方針です。
- 監視分析の「通知メール」は、現状 **実送信ではなくキュー記録のみ**です。

---

## 9. 主な制限・今後の拡張候補

実装上の主な制限:

- テナント切替 UI なし
- owner / admin / viewer の画面メニュー差なし
- 管理画面の一部機能は「準備中」
- 監視通知メールの実送信は未実装
- 会員登録・パスワード再設定 UI なし

設計上の拡張余地:

- 固定カメラ（ONVIF / クラウド）の本格運用 UI
- 観測イベントの汎用一覧・レポート
- 通知チャネル（メール・チャット等）の本実装
- 観測対象テンプレートの追加
