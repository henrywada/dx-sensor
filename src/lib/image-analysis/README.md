# 画像解析処理系列 (`src/lib/image-analysis/`)

「取得した画像から何を読み取るか」を**解析プロバイダの種類ごとにフォルダで分離**する。
`src/lib/sensors/`（データの取得経路）とは独立した関心事であり、
どのセンサー系列で取得した画像であっても、ここの解析プロバイダを組み合わせて使える。

## 現在の系列

| フォルダ | 用途 | 状態 |
|---|---|---|
| `plate-recognizer/` | ナンバープレート認識(ANPR)。駐車場ユースケースの車種・色・プレート番号抽出に使用 | 実装済み |
| `document-ocr/` | 撮影した文書画像から種類プラグインに応じた構造化項目を抽出 | 実装済み |
| `openai-vision/` | 汎用的な画像内容の解析（将来、駐車場以外のユースケースで使用想定） | プレースホルダー（未実装） |
| `aws-rekognition/` | 汎用的な画像内容の解析（コスト・精度面での代替候補） | プレースホルダー（未実装） |

## 新しい解析プロバイダを追加する場合

1. `src/lib/image-analysis/<プロバイダ名>/` にフォルダを作成
2. そのプロバイダ固有のAPIクライアントラッパーを実装（`plate-recognizer/plateRecognizer.ts` を参考に）
3. 呼び出し側（Cron/Ingest APIルート）で、観測対象の種類に応じて呼び出すプロバイダを切り替える
   ロジックを追加する（現状は駐車場ユースケース専用に`plateRecognizer`を直接呼んでいるが、
   将来的には観測対象の`type`列を見てプロバイダを動的に選択する設計に拡張する）

## `change-detection/` との違い

`src/lib/change-detection/frameDiff.ts` は「変化があったかどうか」だけを判定する
軽量な前処理ユーティリティであり、特定の解析プロバイダに依存しないため、
`image-analysis/`には含めず独立させている。
